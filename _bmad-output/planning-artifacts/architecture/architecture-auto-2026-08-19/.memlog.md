- (constraint) Heredado del PRD/UX (no re-decidir): web + app movil con paridad funcional (FR-13/NFR-3). Frontend web: Angular (ultima version) + PrimeNG (preset Aura), definePreset con tokens de DESIGN.md, darkModeSelector por clase. Catalogo curado manualmente por el equipo (FR-14), actualizacion semanal (NFR-1), sin autoservicio de agencias. Alcance geografico MVP: Monterrey, solo vehiculos nuevos. Cuenta simple (email o telefono, FR-15/16) solo requerida al guardar una comparacion; buscar/filtrar/comparar es anonimo. Compartir genera link publico de solo lectura que nunca expira por tiempo. Max 3 vehiculos comparables. NFR-2: busqueda/filtrado <2s. NFR-4: uptime objetivo 99%. NFR-5: flag explicito para esta fase - arquitectura debe permitir escalar a mas ciudades sin rediseno mayor.
- (decision) Backend: .NET (preferencia del usuario, no de mi recomendacion). Nota tecnica investigada: ASP.NET Core Identity no trae un flujo OTP passwordless de un solo metodo como Supabase; requiere ensamblar token providers (2FA/email/SMS token providers) + endpoint custom de sign-in sin password para igualar el flujo de codigo de un solo uso ya diseñado en EXPERIENCE.md (Flujo 2). Se documentara como nota de implementacion, no bloquea la decision de stack.
- (decision) Base de datos: PostgreSQL (via Npgsql EF Core provider). Hosting: Azure. Stack backend confirmado: .NET (ultima LTS/STS, .NET 10 / ASP.NET Core 10 verificado como actual via Context7) + EF Core + Npgsql + PostgreSQL en Azure.
- (decision) App movil: Flutter (decision del usuario, en contra de mi recomendacion de Ionic). Implicacion arquitectonica: dos codebases de frontend separadas (Angular web + Flutter movil/Dart) sin reutilizacion de codigo entre ellas, ambas consumiendo la misma API .NET. Riesgo de consistencia: los tokens de DESIGN.md deben implementarse por separado en ambas plataformas sin drift - se documentara como convencion en el spine.
- (decision) Backoffice de catalogo: seccion admin gated por rol dentro de la misma app Angular (no app separada). Hosting API: Azure Container Apps (plan de consumo, scale-to-zero) en vez de App Service - verificado via web search que es mas barato para trafico bajo/intermitente propio de un MVP en arranque (App Service cobra 24/7 aun sin trafico; Container Apps escala a cero).
- (decision) Estimado de costo mensual aceptado (~35-55 USD/mes: Static Web Apps Standard ~9, Container Apps consumo 0-15, Postgres Flexible B1ms ~16, Communication Services 5-15, Blob Storage 1-2). Decision de producto: OTP favorece email como default, SMS como opcion secundaria, para mantener costo predecible dado que la tarifa de SMS a Mexico no esta confirmada. No incluye dominio, cuotas de app store (Apple 99 USD/año, Google 25 USD unico).
- (event) Reviewer gate ejecutado (rubrica + vigencia tecnologica + seams adversariales). Total 19 hallazgos entre los 3 reviewers. 2 requieren decision del usuario (PrimeNG paso a licencia comercial/community en v22+Angular22; Azure Communication Services no soporta SMS a numeros de Mexico - gap de capacidad, no de precio). El resto son autofixeables: FR-14 backoffice perdido en la destilacion, NFR-2 sin tratamiento arquitectonico, mecanismo de tope de 3 vehiculos poco especifico, AGENCY_BRAND sin AD que lo gobierne, inmutabilidad de comparacion guardada vs link compartido sin definir, modelo de ownership de SavedComparison anonimo-luego-reclamado sin definir, falta contrato OpenAPI para filtros, borrado de vehiculo del catalogo sin definir soft vs hard delete, AD-4 sin piso de seguridad para almacenamiento de tokens.
- (decision) UI kit para Angular: se explorare Spartan, NG-ZORRO (MIT confirmado, tabla robusta), Angular Material (color/tipografia flexibles pero pelea forma/elevacion contra DESIGN.md), Tailwind+CDK desde cero. Decision final: se mantiene PrimeNG (version actual) bajo su Community License (gratis: <1M ingresos anuales, <5 devs, <10 empleados, <3M USD fondeo VC - la startup califica hoy). Riesgo contingente documentado: si el pitch a inversionista cierra una ronda que supere 3M USD VC, o el equipo/ingresos crecen mas alla de esos limites, se activa la licencia comercial (599 USD/dev hasta fin de 2026, luego 799 USD/dev, perpetua con 1 año de updates). Alternativa de reserva si se supera el limite: migrar a Spartan (MIT sin condiciones) o fijar Angular21+PrimeNG21 (MIT permanente).
- (decision) OTP: solo email en el MVP (confirmado). Azure Communication Services no soporta SMS a numeros de Mexico (gap de cobertura, no de precio, verificado contra documentacion en vivo de Microsoft). Telefono/SMS se agrega despues con un proveedor que si cubra Mexico (ej. Twilio), fuera del alcance del MVP.
