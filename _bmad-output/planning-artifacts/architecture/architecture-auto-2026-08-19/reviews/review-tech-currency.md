# Tech Currency Review — [Proyecto Auto] Architecture Spine

## Overall verdict

The backend stack (.NET 10 LTS, ASP.NET Core 10, EF Core 10 + Npgsql, PostgreSQL on Flexible Server, Container Apps consumption vs. App Service) checks out against current web/Context7 sources and was evidently researched rather than guessed — the spine's own "verified via Context7" note for .NET 10 holds up exactly. However, two committed decisions were asserted from what is now stale ground and both land on cost/feasibility, not cosmetics: PrimeNG's "current release" as of Angular 22 is no longer a free MIT dependency, and Azure Communication Services SMS cannot technically reach Mexican phone numbers at all — a fact the spine's own Deferred section mischaracterizes as a pricing question. Azure pricing figures for Static Web Apps and Postgres Burstable B1ms are directionally correct per secondary sources but could not be confirmed against Microsoft's live pricing pages (they render client-side).

## Findings

- **critical** PrimeNG went closed-source for future major versions: PrimeTek archived the MIT repo on 2026-06-29 and PrimeNG v22 (the release that pairs with the "latest" Angular v22 the spine also specifies) ships under the new PrimeUI Commercial/Community dual license, not MIT. Free use now requires meeting and annually re-confirming Community License eligibility (org revenue <$1M, <5 developers, <10 employees, <$3M VC funding); otherwise it's $599/developer perpetual (launch price through 2026, $799 from 2027) plus $399/dev/yr to keep updates. Only PrimeNG ≤21 (capped at Angular ≤21) remains unconditionally MIT; an MIT community fork (Optimus UI / OpenNG) exists but only tracks Angular 21 today with Angular 22 support pending. (Stack table row "PrimeNG | current release compatible with chosen Angular version, Aura preset"; AD-3.) *Fix:* Add an explicit stack note recording this licensing dependency and a fallback decision (accept Community License + eligibility risk, pin to PrimeNG 21/Angular 21, or adopt the MIT fork) — don't let "current release" silently resolve to a paid dependency at implementation time.
- **high** Azure Communication Services SMS does not support Mexico at all, for any sender type. Per Microsoft's live docs (checked 2026-08-19), Mexico phone numbers only support inbound Toll-Free voice calls — zero SMS send/receive capability — and the Sender Type Availability by Country/Region table (Toll-Free, Short Code, 10DLC, Mobile Number, Dynamic/Preregistered Alphanumeric Sender ID) lists no entry for Mexico among its ~26 supported destinations. The product's entire user base is in Monterrey, Mexico. (Deferred section: "SMS OTP channel — v1 or later ... pending confirmation of Mexico carrier surcharges.") *Fix:* Reframe this Deferred item — it isn't a surcharge/cost question, ACS SMS is structurally unusable for this market without Azure's separate "Messaging Connect" partner-routing product (a different integration surface) or a non-ACS SMS provider entirely. If SMS OTP ships at all, the spine should name that dependency now rather than leave it looking like a pricing decision.
- **low** Azure Static Web Apps Standard (~$9/mo) and PostgreSQL Flexible Server Burstable B1ms (~$12/mo) figures are corroborated by multiple independent secondary sources (TrustRadius, Bytebase/dbcost, c3x.dev) and are consistent with long-standing Azure pricing, but Microsoft's own pricing pages render prices client-side via JavaScript and couldn't be scraped directly to independently confirm the exact current number. *Fix:* Re-confirm both via the Azure Pricing Calculator (not the static pricing page) close to implementation time, since neither figure was verifiable against a primary source in this review.
- **informational** Everything else checked out against current sources: Angular is at v22 and Flutter at 3.44/Dart 3.12 as of August 2026, but the spine correctly leaves both as "latest (tracked at implementation time)" rather than pinning a version — not a stale assertion. .NET 10 is confirmed Active LTS (released 2025-11-11, supported to 2028-11-14) via Context7's `/dotnet/core` release notes, exactly matching the spine's claim. Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3 is released and tracks EF Core 10 compatibility. Azure Container Apps consumption plan (scale-to-zero, per-second billing, monthly free grants of 180,000 vCPU-seconds / 360,000 GiB-seconds / 2M requests) is corroborated as cheaper than App Service for low/intermittent traffic by real migration cost examples.
